# 시소 (siso)

좌 성향 커뮤니티와 우 성향 커뮤니티에서 **같은 이슈를 다루는 글을 자동으로 찾아내고**,
양쪽 시각을 AI가 같은 분량으로 정리한 **토론 주제**를 만들어 익명으로 토론하는 서비스입니다.

🔗 **https://siso.ai.kr**

```
[좌 커뮤니티 피드]   [ 놀이터 — AI가 합성한 토론 주제 ]   [우 커뮤니티 피드]
     파랑                  쟁점 배경 / 좌·우 입장                빨강
                        핵심 논거 / 생각해볼 질문
                          댓글 · 입장 투표
```

---

## 왜 만들었나

같은 사건을 두고 커뮤니티마다 전혀 다른 이야기를 합니다. 그걸 비교하려면 사람이 여러 사이트를
돌아다녀야 하고, 그 과정에서 보통 한쪽 이야기만 보게 됩니다. 시소는 그 비교를 한 화면에서
할 수 있게 만드는 실험입니다.

핵심 제약은 **"중립성을 선언이 아니라 시스템으로 강제한다"** 입니다.

- 좌·우 분류는 알고리즘이 아니라 **사람이 소스 단위로 지정**합니다 (개인의 성향을 판단하지 않음)
- UI는 좌·우 전용 컴포넌트를 만들지 않고 `side: 'left' | 'right'` prop 하나로 렌더링합니다
- 합성 결과의 **논거 개수는 적은 쪽에 맞춰 잘라** 한쪽이 많아 보이지 않게 합니다
- 댓글의 성향 표시는 **본인이 선택한 태그만** 사용합니다 (행동 기반 자동 추정 금지)

## 동작 방식

```
원 커뮤니티 (robots.txt 준수, 사이트당 10초 이상 간격)
   │
   ▼  수집 → 중복 체크 → 비속어 필터 → LLM 정치성 분류
 posts
   │
   ▼  ko-sbert 임베딩 (로컬 실행) → pgvector 저장
   │
   ▼  매칭: 좌 글을 시드로 반대 진영 최근접 글을 찾고,
   │        같은 진영에서 유사한 글을 코호트로 붙임 (별 모양 구조)
   │        → 좌·우 각각 최소 N개가 모여야 주제 후보 생성
   │
   ▼  합성: LLM이 제목 + 좌/우 입장 + 쟁점 배경 + 핵심 논거 + 질문 생성
   │        0단계 법적 필터 → 1단계 쟁점 판단 → 2단계 요약 작성
   │        생성 후 별도 모델로 법적 안전성·입장 대비 2차 검사 (fail-closed)
   │
   ▼
topic_pairs → 사이트 노출 → 익명 댓글 · 입장 투표
```

### 설계상 중요한 선택들

| 선택 | 이유 |
|---|---|
| 1:1 매칭이 아니라 **N:M 코호트** | 글 1개씩만 보고 합성했더니 튀는 글 하나가 그 진영의 "입장"이 되는 사고가 있었습니다. 여러 글의 공통 입장을 종합합니다 |
| 코호트를 **별 모양**으로 구성 | 멤버끼리 연결하면 A-B 유사, B-C 유사인데 A와 C는 무관한 주제 이탈이 생깁니다. 모든 멤버를 시드와 직접 비교합니다 |
| 합성과 **검사를 다른 호출로 분리** | "요약을 쓰면서 동시에 대비 여부까지 판단"은 모델 크기와 무관하게 어렵지만, 이미 쓰인 두 입장을 놓고 "이 둘이 다른가"만 좁게 물으면 저렴한 모델도 정확합니다 |
| 운영 파라미터를 **DB 테이블**에 | 임계값 하나 바꾸려고 재배포하지 않습니다. 관리자 화면에서 바꾸고 즉시 되돌립니다 |
| 크롤러가 **DB에 직접 접속** | 배치가 수천 건을 쓰는데 HTTP를 거칠 이유가 없습니다. 스키마 소유권은 백엔드(Flyway)가 갖습니다 |
| 생성량에 **하루 상한** | 임계값만으로는 뉴스 상황에 따라 하루 1건과 8건을 오갑니다. 상한으로 못 박고, 걸린 후보는 다음 날로 넘깁니다 |


## 로컬에서 실행하기

### 1. 의존 서비스
```bash
cd infra && docker compose up -d     # postgres(pgvector) + redis
```

### 2. 환경변수
```bash
cp .env.example .env                 # 값 채우기 (LLM 키 없으면 해당 기능만 비활성)
```
필수: `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ANON_ID_SIGNING_SECRET`
선택: `OPENROUTER_API_KEY`(합성·분류), `RESEND_API_KEY`(뉴스레터), `ASSEMBLY_API_KEY`(청원 위젯),
`RECAPTCHA_*`, `SENTRY_DSN` — 비우면 해당 기능만 조용히 비활성화됩니다.

### 3. 백엔드 (기동 시 Flyway가 스키마 자동 적용)
```bash
cd backend && ./gradlew bootRun      # http://localhost:8080
```

### 4. 프론트
```bash
cd frontend && npm install && npm run dev    # http://localhost:3000
```

### 5. 크롤러
```bash
cd crawler
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
CRAWL_MODE=ingest CRAWL_SIDE=left python -m siso_crawler.run   # 수집(좌)
CRAWL_MODE=postprocess python -m siso_crawler.run              # 임베딩·매칭·합성·정리
```
`CRAWL_MODE`를 비우면 수집과 후처리를 한 프로세스에서 모두 실행합니다(로컬 개발용).

## 테스트

```bash
cd backend && ./gradlew test     # JUnit + Mockito (실제 Postgres 필요: infra compose)
cd crawler && pytest             # 172개, 네트워크 호출 없이 fixture로 파서·파이프라인 검증
cd frontend && npx tsc --noEmit && npm run build
```

CI(GitHub Actions)는 PR마다 **백엔드 테스트(Postgres 컨테이너) + 프론트 빌드 + 크롤러 lint**를
실행합니다. 백엔드는 `ddl-auto=validate`라 엔티티와 마이그레이션이 어긋나면 CI에서 바로 잡힙니다.

## 수집 정책 (중요)

이 프로젝트는 다른 사이트의 공개 게시물을 수집합니다. 아래는 타협하지 않는 규칙입니다.

- **robots.txt를 코드로 강제**합니다. 확인이 불가능하면 수집하지 않습니다(fail-closed).
  단 404(파일 없음)는 업계 관례에 따라 허용으로 처리합니다.
- **사이트당 최소 10초 간격**을 지킵니다. 목록 요청뿐 아니라 상세 페이지 요청에도 적용됩니다.
- **User-Agent에 서비스명과 연락처**를 명시합니다.
- **원문 전체를 복제하지 않습니다.** 화면에는 제목과 원문 링크만 노출하고, 본문 앞부분은
  주제 합성 용도로만 저장합니다.
- 차단·실패가 감지되면 해당 소스를 **자동 비활성화**하고 관리자 알림을 남깁니다.
  IP 차단을 프록시 등으로 우회하지 않습니다.
- 원 커뮤니티나 작성자의 **삭제 요청은 이메일로 접수**해 영업일 기준 24시간 내 1차 검토합니다.

합성 결과는 우리가 게시하는 콘텐츠이므로, 5·18 특별법 등 법적 금지 콘텐츠는 프롬프트 0단계와
별도 모델 2차 검사로 차단합니다. 투표는 이슈 단위만 제공하며 인물·정당 지지 투표는 제공하지
않습니다(공직선거법 리스크 회피). 선거 기간에는 관리자가 '선거 모드'를 켜 API 응답에서 집계를
숨길 수 있습니다.

## 어뷰징 방지

익명 서비스라 "누가 썼는지"를 모르는 대신, 다음 장치들이 실제로 작동하도록 설계했습니다.

- **익명 ID 서명**: `X-Anon-Id`를 그대로 믿으면 아무 UUID나 넣어 레이트리밋·중복 투표 방지를
  전부 우회할 수 있습니다(감사 중 curl로 재현됨). HMAC-SHA256 서명을 함께 검증합니다.
- **레이트리밋 / 급증 탐지**: Redis 고정 윈도 카운터. 급증은 임계값 도달 순간 1회만 알림.
- **신뢰도 가중치**: 같은 IP 해시 군집에서 다수 익명 ID가 생기면 투표·추천 가중치를 낮춥니다.
- **IP는 원본을 저장하지 않습니다.** salt + SHA-256 해시로만 보관하고 90일 후 파기합니다.
- **신고 LLM 분류는 자동 삭제를 하지 않습니다.** 운영자 검수용 힌트만 남깁니다.

## 운영하면서 고친 것들 (요약)

실제 운영 중 발견한 문제와 해결을 기록해 둡니다. 자세한 내용은 `CLAUDE.md`에 있습니다.

| 문제 | 해결 |
|---|---|
| 크롤러가 소스 절반만 처리하고 조용히 종료 (OOM 추정) | 수집(좌/우)과 후처리를 별도 프로세스·스케줄로 분리 |
| 200 OK인데 응답 0바이트로 스로틀 | 스로틀로 감지해 지수 백오프(최대 6시간 쿨다운) |
| 목록 파싱 0건을 "성공"으로 처리해 며칠째 조용히 수집 중단 | 0건을 실패로 집계 → 자동 비활성화·알림 경로 연결 |
| 상세 페이지를 1~2초 간격으로 연속 요청해 차단 유발 | 상세 요청에도 사이트 간격 적용 + 회귀 테스트 추가 |
| 트랜잭션 에러 후 이후 단계가 도미노로 실패 | 단계별 명시적 롤백 |
| 같은 이슈가 매번 새 주제로 쪼개짐 | 중복 판정 임계값·조회 기간을 코호트 설정에서 분리(실측 기반 0.78 / 7일) |
| 주제 생성량이 목표의 5배 | 시간축을 재현하는 백테스트로 재측정 + 하루 생성 상한 도입 |

## 현재 상태와 한계

- 운영 중이며 수집·매칭·합성 파이프라인은 자동으로 돌고 있습니다.
- **미해결**: 일부 커뮤니티가 서버 IP를 차단합니다. 우회하지 않기로 했으므로 해당 소스는
  비활성 상태입니다.
- **프론트엔드 자동화 테스트가 없습니다.** 타입 체크와 빌드가 CI 게이트입니다.
- 광고 수익화는 보류 중입니다. 콘텐츠가 수집·AI 재작성 위주라는 구조적 한계가 있어,
  서비스 고유의 1차 데이터(참여 통계 등)를 만드는 방향을 검토하고 있습니다.
